## T1: Create L2 Message Compound API Skeleton ✅ (v2)
**Completed:** 2026-01-29

**Files created:**
- `apps/web/src/components/ui-custom/chat/message.tsx`

**Implementation (corrected approach):**

The initial implementation incorrectly recreated everything from scratch. The corrected version follows the 3-layer architecture properly:

**L1 Wrapped (from ai-elements):**
- `Message.Root` → wraps `Message` from ai-elements
- `Message.Content` → wraps `MessageContent`
- `Message.Response` → wraps `MessageResponse` (memoized Streamdown)
- `Message.Actions` / `Message.Action` → wraps action components
- `Message.Toolbar` → wraps `MessageToolbar`
- `Message.Reasoning` / `ReasoningTrigger` / `ReasoningContent` → wraps reasoning primitives

**Existing L2 fragments (import separately per linter rules):**
- `ThinkingBlock` - custom reasoning with preview (already exists)
- `ChatStatusMessage.*` - error/cancelled blocks (already exists)
- `ChatMessageFooter` - reveal-on-hover footer (already exists)
- `ChatMessageActions` / `ChatMessageAction` - actions with tooltip/context menu (already exists)
- `ChatMessageInfos` / `ChatMessageInfo` - stats display (already exists)
- `ChatMessageContent` - role-based styling wrapper (already exists)

**Key decisions:**
- NO barrel exports (linter forbids them) - import fragments separately
- NO custom context - use ai-elements context (Reasoning already has `useReasoning()`)
- NO app types duplicated - L2 is app-agnostic, L3 maps MyUIMessage → props
- Thin wrappers only add styling, don't reimplement
- `ThinkingBlock` is the custom reasoning impl with preview + state machine

**What this means for T2-T5:**
- T2: ThinkingBlock already handles A/B/C/D header states - may just need verification
- T3: ChatMessageContent + Message.Response already handle content - verify overflow
- T4: ChatStatusMessage already exists - may just need verification
- T5: ChatMessageFooter/Actions/Infos already exist - verify responsive behavior

**Verified:**
- TypeScript compiles without errors
- No linter errors (no barrel exports)
- Pattern matches architecture guide (L2 wraps L1, no app types)
